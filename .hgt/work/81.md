## Task (verbatim from the issue body)

## Context
#67 jails the `hgt work` session with **no push credentials** — no `~/.ssh`, no `gh` (by design:
fail-closed, can't act as admin `gh`). But the agent's deliverable is *open a PR*. So every attended
sandboxed session dead-ends the same way: the agent commits locally, then can't push, and Carl runs
`git push && gh pr create` by hand from the host. Surfaced dogfooding #65 through the jail.

This isn't a bug — it's the **publish boundary**. It's spec §2's powerless-reader / privileged-actor
split applied to *publish*: the work happens in the powerless jail; pushing a branch + opening a PR is
a privileged action that belongs in a credentialed context. We just haven't paved that step.

## Scope
A host-side publish verb — e.g. `hgt work push <n>` — that:
- resolves the worktree by `<n>` (same N-keyed lookup as `hgt work rm`), from any cwd,
- pushes its feature branch to the remote,
- opens (or updates) the PR, filling from the commits / a template, linking the issue.

Runs **on the host** with Carl's creds, so the jail stays creditless (fail-closed preserved), and the
human deliberately publishes — consistent with the human-is-the-merge-gate philosophy (publish is the
step before review, not an agent superpower).

## Parity (#17)
- **Attended:** the host-side `hgt work push <n>` above.
- **Unattended (listener):** no human to run it, so the jail itself needs the **scoped machine-user
  PAT** via the existing `HGT_SANDBOX_GITHUB_TOKEN` seam (ADR 0005 residual) **plus** egress to the
  git remote (#74). Same publish boundary, credential injected instead of host-side.

## Non-goals
- Provisioning the scoped machine-user PAT itself — its own slice.
- The listener/executor.
- Merge — stays a human action on the PR; this only gets the branch/PR *up* for review.

## Acceptance criteria
- [ ] `hgt work push <n>` pushes the issue's worktree branch and opens/updates its PR, run from the host, from any cwd.
- [ ] The jailed session still holds no push credential (the boundary is preserved, not punched).
- [ ] Idempotent: re-running on an already-pushed branch updates rather than errors.

## Dependencies / ordering
Follows #67 (PR #70). Ties to the `HGT_SANDBOX_GITHUB_TOKEN` residual + #74 (remote egress) for the
unattended path. If the clone pivot lands, publish becomes an even more explicit boundary (push from
the clone / fetch-back) — the verb still fits.
