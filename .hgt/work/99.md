## Task (verbatim from the issue body)

## Context
`hgt-review.yml`'s collect step filters review *threads* by `isResolved` but then feeds every comment inside a surviving thread. GitHub's minimize (outdated / off-topic / resolved / spam) is invisible to the query, so a hidden comment reaches the agent as outstanding feedback and earns a reply. `claude-code-action` already drops these (`c.isMinimized`, `src/github/data/fetcher.ts`) — steal it. Surfaced reviewing #88.

## Scope
The collect step's GraphQL query + jq in `.github/workflows/hgt-review.yml`:
- add `isMinimized` to `reviewThreads.nodes.comments.nodes`
- `select(.isMinimized | not)` when building the feedback block
- a thread whose comments are all minimized must emit no section — not a bare `### Unresolved thread` header with nothing under it

Decide and encode: an unresolved thread with every comment minimized still counts toward `unresolved` and sets `has_feedback=true`, so the agent runs against an empty feedback block and the fail-loud guard turns it red. Either exclude such threads from the count or keep them and document why.

## Non-goals
Comment-text sanitization (invisible unicode / HTML comments) — separate follow-up. The `isResolved` logic itself, which is correct.

## Acceptance criteria
- [ ] Minimized comments never reach the prompt
- [ ] An all-minimized thread emits no section
- [ ] No run can go red purely because every outstanding comment was minimized
